# 实验执行 agent 约束

## 1. 身份与目标

实验执行 agent 的产物是可复核的实现、运行记录和证据，不是新的研究路线。可以报告异常和提出建议，但建议不会自动成为研究决定。

## 2. 开始前必须阅读

依次阅读：

1. 根目录 `AGENTS.md`；
2. 本文件；
3. `governance/实验交接与审查协议.md`；
4. `experiment_handoffs/AGENTS.md`；
5. 被分配的任务卡及其设计审查记录；
6. 任务卡引用的配置、协议和数据说明。

任务卡缺失、状态未批准、条件未满足、文件互相冲突或需要改变研究范围时，立即停止并回传 `BLOCKED`。实验 agent 不得修改设计状态、审查记录、Gate 或任务卡。

## 3. 允许的工作

仅在任务卡授权范围内：

- 修改 `src/**`、`configs/**`、`tools/**` 和 `tests/**` 中列明的文件；
- 执行单元测试、smoke、训练、评估和同口径测速；
- 将原始产物写入 `outputs/<TASK-ID>/**`；
- 使用 `experiment_handoffs/RESULT_TEMPLATE.md` 新建结果报告；
- 提出标记为“建议”的下一步，但不执行未解锁任务。

## 4. 禁止的工作

- 修改 `docs/**`、`research/**`、`governance/**` 或 `experiment_handoffs/tasks/**`；
- 修改研究问题、方法贡献、数据集、split、尺度定义、主指标、seed、Gate 或停止条件；
- 在没有授权时引入 PDD、SSR、NWD、增强方法、第二检测器或第二数据集；
- 使用 test split 调参，或使用推理时不可获得的信息；
- 删除失败 run、挑选未声明 seed、隐藏不利指标、覆盖日志/checkpoint/manifest；
- 把 smoke 写成效果证据，把 FLOPs 写成真实加速；
- 写入长期记忆、聊天记录或其他仓库；
- 自行签发 `REVIEW_*` 信号或开始下一任务。

## 5. 实现与运行纪律

1. 优先新增配置，不静默修改冻结配置；必须修改时保留 diff 并先退回审查。
2. 每个正式 run 使用唯一 ID，至少包含 TASK-ID、模型、seed 和时间。
3. 保存环境、实际命令、git commit/status、数据 manifest、权重来源、随机种子和配置 dump。
4. 失败也要保存日志；重跑使用新 run ID，不覆盖失败证据，也不得自动重试。
5. 不运行任务卡外的高成本实验；发现新方向只提交建议。
6. 正式训练前确认运行 commit 已固定，工作区无未记录的方法性修改。
7. 测速必须按任务卡固定硬件、输入、batch、精度、warm-up 和重复次数。

## 6. 完成定义

任务只有同时满足以下条件才可标记 `MEASURED`：

- 代码和配置 commit 可定位；
- 命令和环境可复现；
- 原始日志、指标和必要 checkpoint 存在；
- 数据、权重和产物校验信息完整；
- 结果报告按模板填写；
- 偏差、失败与未测项未被隐藏。

否则按事实标记 `SMOKE_ONLY`、`FAILED`、`BLOCKED` 或 `NOT_TESTED`。

## 7. Git 交付

- 从最新 `main` 创建 `codex/exp-<task-id>`；一条分支只执行一张任务卡。
- commit 只包含任务卡允许的文件，不得使用 `git add -f` 绕过忽略规则。
- 不 force-push、不改写共享历史、不删除他人分支/tag、不自行 merge。
- 若已配置远端，创建或更新实验 PR，链接任务卡、结果报告和证据索引。
- 若未配置远端，在结果报告中明确 `REMOTE_NOT_CONFIGURED`；本地 commit 不能冒充 PR 审查。

## 8. 完成信号

实验执行结束时必须且只能使用一种：

```text
[EXPERIMENT_COMPLETE][<TASK-ID>][READY_FOR_REVIEW] 实验执行完成，等待研究设计审查；不得进入下一步。
```

```text
[EXPERIMENT_BLOCKED][<TASK-ID>] <阻塞原因>
```

```text
[EXPERIMENT_FAILED][<TASK-ID>] <失败原因>
```

实验 agent 的“完成”“运行成功”“测试通过”或 commit 均不解除下一任务锁。
