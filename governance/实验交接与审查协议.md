# 实验交接与审查协议

本协议定义研究设计 agent 与实验执行 agent 之间唯一有效的任务生命周期。默认原则是：下一任务锁定，实验完成不等于研究通过。

## 1. 生命周期

```text
研究问题
  -> 任务卡 DRAFT
  -> 设计审查
  -> APPROVED / APPROVED_WITH_CONDITIONS
  -> 实现与 smoke
  -> 正式运行
  -> EXPERIMENT_COMPLETE / BLOCKED / FAILED
  -> 结果审查
  -> REVIEW_PASSED / WITH_CONDITIONS / BLOCKED / REVISION_REQUIRED / REJECTED
  -> 明确解锁下一 TASK-ID 或继续锁定
```

任何中间口头描述、测试通过、训练结束、commit、push 或 PR 状态均不能跳过上述阶段。同一 agent/session 不得同时承担某一 TASK-ID 的实验执行和正式结果批准。

## 2. 三类状态不得混用

### 2.1 设计审查状态

- `DRAFT`
- `APPROVED`
- `APPROVED_WITH_CONDITIONS`
- `REVISION_REQUIRED`
- `REJECTED`

### 2.2 实验执行状态

- `PLANNED`
- `SMOKE_ONLY`
- `RUNNING`
- `MEASURED`
- `FAILED`
- `BLOCKED`
- `NOT_TESTED`

### 2.3 研究结果审查状态

- `REVIEW_PASSED`
- `REVIEW_PASSED_WITH_CONDITIONS`
- `REVIEW_BLOCKED`
- `REVISION_REQUIRED`
- `REVIEW_REJECTED`

例如，实验状态 `MEASURED` 只代表存在原始测量产物，不代表 `REVIEW_PASSED`。

## 3. 任务卡冻结

- 任务卡由研究设计 agent 创建和维护，实验执行 agent 只读。
- 一旦首次正式运行开始，任务卡正文冻结。
- 如需改变问题、数据、split、模型、seed、预算、指标、Gate 或停止条件，必须新增 `<TASK-ID>-amendment-N.md` 并重新设计审查。
- 修订不得删除旧任务卡、被驳回意见或已产生的失败证据。
- 修复不改变科研变量的明确实现错误，可由研究设计 agent 在修订记录中限定范围后继续当前任务。

## 4. 执行前检查

实验执行 agent 必须逐项确认：

1. 当前分支是 `codex/exp-<task-id>`，基于已审阅 `main`；
2. 任务卡和设计审查记录可定位；
3. 设计状态允许当前阶段执行；
4. `APPROVED_WITH_CONDITIONS` 的当前阶段条件已有证据；
5. 数据、权重、配置、环境和输出目录不会覆盖既有产物；
6. 运行 commit 已固定；
7. 下一任务仍为 `LOCKED`。

任一项不满足，回传 `[EXPERIMENT_BLOCKED]`，不得自行补充研究决定。

## 5. 实验回传

实验执行 agent 使用 `experiment_handoffs/RESULT_TEMPLATE.md`。报告必须包含：

- 对应任务卡、设计审查、commit 和 PR/远端状态；
- 实际修改文件、环境、数据、权重、命令和配置；
- 每个 run 的状态及原始日志、checkpoint、指标路径和校验信息；
- 与任务卡的全部偏差；
- 失败、异常、未测项和有限解释；
- 唯一实验完成信号。

同一任务重跑使用 `<TASK-ID>-rerun-N.md` 和新 run 目录，不覆盖旧报告。

## 6. 研究结果审查

研究设计 agent 使用 `research/reviews/RESULT_REVIEW_TEMPLATE.md`，不得只复述实验报告。至少检查：

- 授权范围和设计版本；
- 数据版本、split、类别与尺度口径；
- 配置差异、初始化和训练预算；
- 原始日志、checkpoint/hash、指标复算与失败 run；
- 是否存在泄漏、选择性报告、机械指标收益或不公平对照；
- Gate 是否逐项满足；
- 竞争解释是否仍可解释全部结果。

无可审查正式实验时必须用 `REVIEW_BLOCKED`，不能把 smoke 或准备工作写成通过。

## 7. 法定信号

### 实验执行 agent

```text
[EXPERIMENT_COMPLETE][<TASK-ID>][READY_FOR_REVIEW] 实验执行完成，等待研究设计审查；不得进入下一步。
[EXPERIMENT_BLOCKED][<TASK-ID>] <阻塞原因>
[EXPERIMENT_FAILED][<TASK-ID>] <失败原因>
```

### 研究设计 agent

```text
[REVIEW_PASSED][<TASK-ID>] 审查通过，可以进入 <NEXT-TASK-ID>。
[REVIEW_PASSED_WITH_CONDITIONS][<TASK-ID>] 附条件通过；满足 <条件> 后可以进入 <NEXT-TASK-ID>。
[REVIEW_BLOCKED][<TASK-ID>] 未产生可审查实验；解除 <阻塞条件> 后继续当前任务，不得进入下一步。
[REVISION_REQUIRED][<TASK-ID>] 需要补充或重跑；不得进入下一步。
[REVIEW_REJECTED][<TASK-ID>] 审查不通过；停止进入下一步。
```

实验 agent 禁止发出 `REVIEW_*`；研究设计 agent 不得把 `EXPERIMENT_COMPLETE` 当作科研结论。

## 8. 锁定规则

- 所有未来任务默认 `LOCKED`。
- 只有 `REVIEW_PASSED` 或满足明确条件后的 `REVIEW_PASSED_WITH_CONDITIONS` 可以解锁一个具名下一任务。
- 放行信号未写下一 TASK-ID、证据审查不完整或审查文件未提交时，视为未放行。
- 用户可以随时停止或改变方向；研究设计 agent 必须将变化版本化，实验 agent 不得自行解释为授权。
