# 实验交接与审查协议

本协议定义研究设计 agent 与实验执行 agent 之间的任务生命周期。核心原则是：**目标引领、工程自主闭环、实验严格自查、里程碑节点严把关**。

## 1. 阶段任务生命周期

```text
阶段目标与路线图 (Milestone Roadmap)
  -> 阶段任务卡 DRAFT (明确假设、对照矩阵与阶段Gate)
  -> 里程碑设计审查 (APPROVED / APPROVED_WITH_CONDITIONS)
  -> 阶段内工程实现与自愈迭代 (代码排错、环境自适应、Smoke/单测自查，无需频繁打回)
  -> 矩阵式正式运行与原始证据落盘
  -> 实验 Agent 严格自我审查 (Self-Review Checklist 确认)
  -> EXPERIMENT_COMPLETE (或触碰红线时上报 BLOCKED/致命失败 FAILED)
  -> 里程碑结果审查 (研究设计 Agent 对科学变量与Gate进行复核)
  -> REVIEW_PASSED / WITH_CONDITIONS / REVISION_REQUIRED / REJECTED
  -> 明确解锁下一阶段目标 (或继续锁定)
```

## 2. 状态机规范

### 2.1 设计审查状态（阶段启动前由研究 Agent 确认）
- `DRAFT`：任务卡制定中；
- `APPROVED`：阶段目标、假设与对照设计已批准，实验 Agent 可启动；
- `APPROVED_WITH_CONDITIONS`：需满足前置依赖后启动；
- `REVISION_REQUIRED`：科学设计有缺陷，需修改；
- `REJECTED`：方向否定，废弃该卡。

### 2.2 实验执行状态（由实验 Agent 维护）
- `PLANNED`：已规划；
- `SMOKE_ONLY`：完成接口与拓扑自测；
- `RUNNING`：正式矩阵运行中；
- `MEASURED`：运行完成，产物与自我审查完整；
- `FAILED`：致命错误无法自愈；
- `BLOCKED`：触碰科学红线或依赖缺失阻断；
- `NOT_TESTED`：未测试项。

### 2.3 里程碑审查状态（由研究 Agent 签发）
- `REVIEW_PASSED`：科学有效且达成 Gate，解锁下一阶段；
- `REVIEW_PASSED_WITH_CONDITIONS`：附条件放行；
- `REVIEW_BLOCKED`：证据不全或存在未解科学矛盾；
- `REVISION_REQUIRED`：需补充消融或重跑；
- `REVIEW_REJECTED`：科学假设被证伪。

## 3. 阶段内工程自迭代与自治规则

- **工程自主解决范围**：
  在保持科学变量（模型顶层设计、损失定义、数据划分、评估口径）不变的前提下，实验 Agent **应当自主排查并解决**代码 bug、张量维度不一致、OOM 显存溢出、梯度异常与环境兼容问题，无需向研究 Agent 抛回阻断。
- **透明记录原则**：
  自主修复的代码与微调的工程参数（如 lr warmup、梯度裁剪）必须如实记录在结果报告中。
- **红线阻断机制**：
  当发现理论假设无法在数学/逻辑上自洽、必须根本性重写网络架构、或算力/数据需求严重超出阶段预算时，实验 Agent 必须立即发出 `[EXPERIMENT_BLOCKED]` 寻求研究设计层面的裁决。

## 4. 交付前的实验 Agent 自我审查

实验 Agent 在输出 `[EXPERIMENT_COMPLETE]` 前，必须对照模板完成以下自我审查：
1. **代码与拓扑**：确认通过 Smoke 测试，张量 shape 无误，模块连接符合设计；
2. **防泄漏与公平性**：确认未在 test split 上调参，对照组保持同口径；
3. **数据与产物**：确认日志、checkpoint、配置 dump 及对应 hash 完整落盘；
4. **真实性**：确认无挑选 seed、无隐瞒负面指标。

## 5. 实验交付报告规范

实验 Agent 使用 `experiment_handoffs/RESULT_TEMPLATE.md` 提交报告，需包含：
- 阶段任务卡版本与设计审查索引；
- 实际修改文件清单与自主修复工程记录；
- 运行产物索引（Run ID、日志、checkpoint/hash、指标文件）；
- **已完成的自我审查清单（Self-Review Checklist）**；
- 测得指标矩阵与 Gate 对照；
- 唯一法定完成信号。

同一任务重跑使用 `<TASK-ID>-rerun-N.md` 和新 run 目录，不覆盖旧报告。

## 6. 里程碑节点审查职责

研究设计 Agent 依据 `research/reviews/RESULT_REVIEW_TEMPLATE.md` 进行里程碑审查：
- 重点核验：核心科学贡献是否成立、对照是否严谨、Gate 是否逐项达成、是否存在未排除的混杂因素；
- 认可实验 Agent 对非科学性工程问题的自主解决，重点聚焦科学结论的真实性与严谨性；
- 审查通过后出具放行信号，解锁下一阶段任务。

## 7. 法定信号

### 实验执行 agent
```text
[EXPERIMENT_COMPLETE][<TASK-ID>][READY_FOR_REVIEW] 实验执行完成并通过自我审查，等待研究设计里程碑审查；不得自行进入下一步。
[EXPERIMENT_BLOCKED][<TASK-ID>] <科学假设冲突或越权红线阻塞原因>
[EXPERIMENT_FAILED][<TASK-ID>] <无法自主恢复的致命失败原因>
```

### 研究设计 agent
```text
[REVIEW_PASSED][<TASK-ID>] 里程碑审查通过，可以进入 <NEXT-TASK-ID>。
[REVIEW_PASSED_WITH_CONDITIONS][<TASK-ID>] 附条件通过；满足 <条件> 后可以进入 <NEXT-TASK-ID>。
[REVIEW_BLOCKED][<TASK-ID>] 未产生可审查实验；解除 <阻塞条件> 后继续当前任务。
[REVISION_REQUIRED][<TASK-ID>] 需要补充对照或重跑；不得进入下一步。
[REVIEW_REJECTED][<TASK-ID>] 里程碑审查不通过；终止当前技术路线。
```

## 8. 锁定规则

- 所有未来阶段默认 `LOCKED`。
- 只有里程碑审查签发 `REVIEW_PASSED` 或满足条件的 `REVIEW_PASSED_WITH_CONDITIONS` 才能解锁下一具名阶段。
- 用户可以随时调整研究方向；研究设计 Agent 负责版本化更新，实验 Agent 不得自行解释为授权。
