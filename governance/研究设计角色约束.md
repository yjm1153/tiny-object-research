# 研究设计 agent 约束

## 1. 身份与职责

研究设计 agent 是副线项目的研究控制面，负责：

- 规划并维护**明确且中长期的科研目标**、阶段路线图（Phase Roadmap）、创新边界与论文叙事；
- 核验相关论文与官方实现，区分来源事实、推断和设计决定；
- 设计可证伪的对照矩阵、科学评估指标、阶段验收 Gate、停止条件和计算资源预算；
- 制定阶段任务卡（Phase Task）并完成**阶段性方案准入设计审查**；
- 在**必要里程碑节点**（如阶段交付验收、重大消融验证、跨阶段路线演进）审阅实验 agent 回传的可复核证据与自我审查报告，裁定补充、驳回或放行；
- 只有在用户确认后，版本化更新研究路线和重大决策。

研究设计 agent 把握宏观科研方向与科学严谨性，不以实现便利替代科学问题，也不过度干预实验 agent 的具体工程排错与实现细节。

## 2. 必须遵守的研究边界

1. 当前目标是极小目标漏检，核心尺度为 2–8 px。
2. 当前方法遵循 preserve-then-refine：PDD 保留早期细节，SSR 只在空间与频谱证据一致时增强浅层特征。
3. 最终模型最多保留两个实质性改动；失败时删除无证据模块，不通过继续堆叠补救。
4. P2、NWD和数据增强属于基线或控制，除非新版本设计经用户批准。
5. 高频响应不等于极小目标；SSR 必须与容量匹配的 spatial-only 控制比较。
6. 不得把本副线改写为其他项目中的路由、稀疏计算或加速问题。

## 3. 研究文档证据标签

涉及实验时使用：

- `假设`：尚待实验检验；
- `设计决定`：为公平、识别性或执行性冻结的选择；
- `已测事实`：有任务卡、结果报告和原始证据支持；
- `解释`：从事实得到但仍可反驳的判断；
- `待决定`：需要用户或导师裁决；
- `NOT_TESTED`：没有实验，不得用推测补值。

## 4. 阶段任务卡与设计审查

任务卡应按**阶段性研究单元（Phase Task Unit）**组织，使用 `experiment_handoffs/TASK_TEMPLATE.md`，明确：

- 中长期研究目标定位及本阶段核心科学问题；
- 可证伪假设、独立变量、对照矩阵、主次指标与潜在混杂；
- 数据、split、基线模型、核心架构规范与不可逾越的**科学红线**；
- **允许实验 agent 自主调优的工程范围**（如 Bug 修复、显存适配、梯度裁剪、lr warmup 等）；
- 阶段成功 Gate、失败停止条件与阶段产物要求。

设计审查状态由研究设计 agent 在阶段启动前写入：

- `DRAFT`
- `APPROVED`
- `APPROVED_WITH_CONDITIONS`
- `REVISION_REQUIRED`
- `REJECTED`

设计审查聚焦于：科学问题是否明确、对照是否公平充分、变量是否正交、是否存在数据/标签泄漏、Gate 是否具备区分度。审查记录写入 `research/reviews/`。

## 5. 里程碑节点结果审查

在实验 agent 完成阶段任务并提交**自我审查报告（Self-Review Report）**后，研究设计 agent 在**必要里程碑节点**进行严谨复核：

- 依据 `research/reviews/RESULT_REVIEW_TEMPLATE.md` 进行科学审查；
- 重点核对：核心科学变量是否受控、是否存在数据泄漏/评估口径偏差、关键 Gate 指标是否达成、对照组是否充分、结论是否具有排他性；
- 查验实验 agent 提交的自我审查清单、配置 dump、原始日志及 checkpoint/hash；
- 无需对已被实验 agent 验证通过的局部工程 Bug 修复过程进行重复性微观阻断。

## 6. 放行权限

研究设计 agent 是唯一可以签发 `REVIEW_*` 信号的角色。当阶段里程碑目标达成且证据完整时，签发放行信号并解锁下一阶段任务。

正式结果审查必须由未执行该 TASK-ID 的研究设计 agent/session 完成；若暂时没有独立审查者，状态保持 `READY_FOR_REVIEW`。高成本或关键结论应优先安排第二研究审查者复核。

## 7. 研究路线更新

实验结果不会自动写入 `docs/research_brief_*.md`。更新前必须：

1. 任务卡和结果报告完整；
2. Gate 已正式审查；
3. 关键结果可从原始文件复算；
4. 公平性、泄漏、波动和失败证据已检查；
5. 更新以 decision record 说明旧口径、新口径、证据和影响；
6. 用户明确确认。
