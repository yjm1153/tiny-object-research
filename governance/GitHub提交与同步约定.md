# GitHub 固定提交与研究—实验同步约定

Git commit、Pull Request、交接文件和正式信号共同构成副线项目的可追溯同步面。它们不改变研究边界，也不替代科学审查。

## 1. 分支责任

- `main`：经审阅的稳定状态。
- `codex/research-<topic>`：研究设计、任务卡、设计/结果审查、治理和研究文档。
- `codex/exp-<task-id>`：一张已批准任务卡对应的实现、测试、运行与结果报告。

实验分支从最新 `main` 创建。研究治理和实验实现不得混在同一分支；需要衔接时先审阅/合并治理分支，再 rebase 或重建实验分支。

## 2. 固定提交点

| 触发点 | 负责人 | 必须提交的内容 |
|---|---|---|
| 任务卡和设计审查冻结 | 研究设计 agent | 任务卡、审查记录、Gate、允许范围和锁定状态 |
| 正式运行前 | 实验执行 agent | 实现、配置、测试、精确命令、运行 commit 和环境准备证据 |
| 实验完成/失败/阻塞 | 实验执行 agent | 结果报告、轻量证据索引、实际命令、偏差和完成信号 |
| 结果审查完成 | 研究设计 agent | 审查记录、Gate 判定、法定信号和下一任务锁定/解锁 |
| 回应审查意见 | 原提交角色 | 仅包含具名修订，不混入新问题或新任务 |

数据集、权重、checkpoint、大日志和本地环境不进入 Git。轻量 JSON、CSV、manifest、校验和及远端证据路径可以提交。

## 3. 双向同步

### 实验执行 agent -> 研究设计 agent

1. 提交 `codex/exp-<task-id>`；
2. 更新 `experiment_handoffs/results/<TASK-ID>.md`；
3. 记录 commit、PR URL或远端状态、证据路径和唯一实验信号；
4. 遇到阻塞、失败、协议偏差或核心变量变更需求时立即交接，不等待正常结束。

### 研究设计 agent -> 实验执行 agent

1. 在 `research/reviews/` 新建不可覆盖的审查记录；
2. 提交 `codex/research-<topic>`；
3. 在实验 PR 或交接消息中同步审查文件、可执行修订和法定审查信号；
4. 仅在证据核验后解锁具名下一任务。

## 4. 远端与 PR

- 已配置远端时，固定提交点应 push，并创建或更新对应 PR。
- PR 必须链接任务卡、设计审查、结果报告、测试状态、未测项、协议偏差和原始证据位置。
- 未配置远端时，不得伪造 PR URL；报告 `REMOTE_NOT_CONFIGURED`，使用本地 commit 作为临时可追溯点。
- 配置远端后，应补推既有审阅分支并建立 PR；此前的本地 commit 不自动获得审阅状态。

## 5. 禁止操作

- 直接在 `main` 开展普通任务；
- force-push、共享历史改写、删除他人分支/tag；
- 未经授权 merge；
- 使用 `git add -f` 提交被忽略的大型或敏感产物；
- 用 commit、push、PR 或 CI 绿灯替代 `EXPERIMENT_COMPLETE` 或 `REVIEW_PASSED`。

## 6. 正式交接最低条件

没有以下四项的口头进度不构成正式交接：

1. 新的可定位 commit；
2. 任务卡或结果/审查文件；
3. 原始证据路径或明确 `NOT_TESTED/BLOCKED`；
4. 与角色权限一致的法定信号。
